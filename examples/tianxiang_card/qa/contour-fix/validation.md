# 轮廓反射修复验证 · 2026-09-22

问题：旧 height/medium 使用 `(1 - foil) × line × .28 × contourStrength × effectPower`，默认静止核心只覆盖约 1.4% 剩余亮度，亮色卡面上的轮廓几乎不可见；原组件测试使用全黑轮廓，未覆盖可见性。

最终实现：共享 contour_material.glsl，用与镭射相同的指针光源驱动斜向反射亮带。转动改变亮带位置，源图与轮廓 UV 固定；核心和两级光晕在亮带外淡出。局部恢复亮度空间，限制能量，保留默认 .35 轮廓强度。foilStrength 独立控制镭射，effectStrength=0 仍关闭全部光效。low 默认材质与参考实现的像素对照继续通过。

验证：模板 Flutter analyze 与 15 个组件测试通过；示例 analyze、3 个测试及 Web debug 构建通过。新增真实卡图测试在宽 320 的渲染中比较轮廓开/关、镭射开/关、静止/激活，检查可见像素、未受影响区域、平均亮度差、Alpha 和全光效关闭。关闭镭射和景深后，左右姿态的反射能量中心从约 .413 移动至 .646，验证轮廓自身响应角度，而非仅依赖整卡镭射变化。

浏览器 1280×1000 检查了 height 左/右、medium 相同右姿态轮廓开/关，以及 medium 仅轮廓；可见高光随角度移动、线条与源图贴合。对应截图与测试输出存于本目录。验证范围为 Flutter 测试渲染器和 Web；本次未做原生设备验证。旧 v2 素材及其证据保持原样，当前记录只覆盖此次运行时材质修复。
